# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A small to-do app in plain HTML/CSS/JS, used for a hands-on Claude Code training session. It has no framework, bundler or runtime dependencies (see `docs/adr/ADR-001-plain-js-no-build.md`). Keep it that way: don't add npm packages, a build step, or ES module syntax.

## Commands

Requires Node 16.17+ and Python 3. `npm install` installs nothing; it only satisfies the lockfile.

```bash
npm test                                   # node --test tests/
node --test tests/todos.test.js            # one test file
node --test --test-name-pattern="addTask" tests/   # tests matching a name (Node 18.11+)
npm start                                  # python -m http.server 8000 -> http://localhost:8000
```

`.claude/launch.json` defines the same server as `todo-app` on port 8000 for the preview browser. There is no linter or formatter configured.

## Architecture

There are two script files, and keeping them separate is what makes the app testable:

- **`todos.js`** holds the task logic as pure functions (`addTask`, `toggleTask`, `removeTask`, `clearDone`, `filterTasks`, `countRemaining`, `sampleTasks`). Every function returns a new array and never mutates its input. It has no DOM access. It loads in the browser through a plain `<script>` tag, so its functions become globals, and it exports to Node with a guarded `if (typeof module !== "undefined") module.exports = {...}`. Add any new function to that export block as well, or the tests can't see it.
- **`app.js`** is the browser UI. It holds module-level state (`tasks`, `filter`), and every change goes through `update(next)`, which replaces `tasks` with the new array from a `todos.js` function and calls `render()`. `render()` rebuilds the whole list and then saves to `localStorage` under the key `training-todos`. If nothing is stored, or what is stored is invalid, `load()` falls back to `sampleTasks()`. Task text the user types is put on the page with `textContent`, and `innerHTML` is used only for the fixed "Nothing here." message. Keep it that way, or text typed into a task can run as HTML.
- `index.html` must load `todos.js` before `app.js`.

A task is `{ id, text, done }`, where `id` is a random base-36 string generated by `makeTask`. New fields (for example the "due date" exercise in the sample tasks) need to be added to `makeTask`, to the `todos.js` functions that build tasks, and to the rendering in `app.js`.

Tests use Node's built-in `node:test` and `node:assert`, and only cover `todos.js`. There are no DOM tests, so check UI changes by hand in the browser.

## Training setup notes

- `SAMPLE_TASKS` in `todos.js` doubles as the list of lab exercises, and `tests/todos.test.js` checks that there are exactly five tasks and that the first one is done. If you change the sample list, update that test too.
- `training/templates/` holds the finished lab files that attendees copy to the repo root if they fall behind (see the README table). Make lab changes in the root files, not in the templates. `training/templates/CLAUDE.md` is a copy of this file, so update both together.
- Permission rules in `.claude/settings.json` (copied from `training/templates/.claude/settings.json` during the lab) are only read when a session starts. After changing them, start a new session.
- `.env` (copied from `.env.example`) contains only a fake key. It exists so attendees can check that Claude is blocked from reading it. Nothing in the app uses it, so don't read or modify it.
- `docs/adr/` holds architecture decision records (`ADR-NNN-title.md`, with Status/Date, Context, Decision and Consequences sections). Record new architectural decisions there in the same format.
